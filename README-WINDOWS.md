# ytm-rs для Windows 11 x64

Исходная версия зафиксирована на [grapedjuice/ytm-rs](https://github.com/grapedjuice/ytm-rs/commit/a3a0b991fa811e5a023d4a66e2e62eb3857c6850). Исходники распространяются по GPL-3.0-only. Лицензия, исходники локальных изменений зависимостей и файлы сборки входят в архив.

## Сборка и запуск

Нужны актуальный стабильный Rust, инструменты C++ MSVC и Windows SDK. В PowerShell из корня проекта выполните:

```powershell
cargo check --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --locked --release
Copy-Item installer\portable.txt target\release\portable.txt
.\target\release\ytm-rs.exe
```

Portable-версия хранит настройки и кэш в папке `data` рядом с EXE. Для установленной версии путь по умолчанию — `%APPDATA%\ytm-rs-windows\data`. Сеанс Google хранится в Windows Credential Manager, при переносе на другой компьютер нужно войти снова.

С установленным Inno Setup можно выполнить `iscc installer\ytm-rs.iss`. GitHub Actions → **Windows client** собирает portable-архив, соответствующие исходники и отдельный установщик. Автообновление на Windows по умолчанию выключено. При включении оно проверяет релизы репозитория `zawkiel/ytm-rs`.

## Discord

1. Создайте приложение в [Discord Developer Portal](https://discord.com/developers/applications). Укажите имя, которое будет видно в профиле.
2. Скопируйте **General Information → Application ID** и вставьте его в **Настройки → Discord**. Нажмите Enter или выйдите из поля.
3. Откройте настольный Discord, включите показ активности в его настройках и запустите трек. Строка «Подключение» показывает состояние локального соединения.
4. В настройках плеера можно скрыть активность на паузе или убрать обложку, прогресс и кнопку. Кнопка видна другим пользователям Discord. Если активность остаётся на паузе, таймер убирается до продолжения воспроизведения.

Для сборки с заранее заданным публичным ID установите `YTM_DISCORD_ID` перед запуском Cargo. Переменная также читается при запуске, если поле настроек пустое.

## Возможности и зависимости

Из ytm-rs сохранены Главная и рекомендации, поиск, вход в Google, библиотека, плейлисты и лайки, очередь, повтор, перемешивание, радио и автопроигрывание, обложки, тексты, мини-плеер, полноэкранный режим, тёмная тема и русский и английский интерфейс. Сохранены системные медиаклавиши, трей и закрытие в трей. Автозапуск включается в разделе **Настройки → Основные → Окно**.

egui/eframe рисует интерфейс, rodio и Symphonia воспроизводят звук. Сетевые задачи выполняет общий Tokio runtime и переиспользуемый reqwest-клиент. QuickJS используется для разрешения подписанных потоков. Имеющийся резервный путь yt-dlp может использовать Node.js, Deno или QuickJS для отдельных треков. На время этого вызова используется временный файл cookies, который исходная реализация удаляет после вызова или при следующем запуске. Вход и проверка у некоторых провайдеров текстов открывают временное окно WebView2 в дочернем процессе.

## Состояние проверок

Полную сборку и запуск предстоит проверить в среде, где Cargo может загрузить зафиксированные зависимости. Замеры Windows для этого исходного архива отсутствуют. Для сравнения с исходной версией измеряйте Working Set и Private Bytes через 30 секунд после запуска, через 30 минут воспроизведения и после 100 успешных смен трека. Усредняйте загрузку CPU на одинаковых интервалах в простое и при проигрывании. Сохраняйте одинаковые размер окна, тему, список треков и состояние Discord. Отдельно проверяйте чистый профиль и авторизованный профиль. Для воспроизводимой смены треков у проекта есть тестовые переменные `YTM_SMOKE`, `YTM_SKIP` и `YTM_LOG`.
